Quantum Ready · scan pipeline

How the scanner works

You give it one domain. It gives back a risk report, a cryptographic inventory and a migration plan — by measuring what your servers actually do, not by asking anyone to fill in a questionnaire.

Six stages run in order. Each one is a measurement, and each feeds the next. Nothing is scored until the final stage, so every number in the report traces back to something observed on the wire.

The six stages

1

Find everything you own

scan/discovery.py · Scanner._discover

inacme.co.uk→outlive hostnames

Public Certificate Transparency logs record every certificate ever issued for your domain, so they double as a list of hostnames you may have forgotten about. The scanner reads those logs, and falls back to guessing common names (www, mail, api…) if the logs come back empty.

Then it throws away anything that no longer resolves in DNS. That matters: CT logs remember hosts for years after they're switched off, and a report padded with dead names is worse than no report.

  • hostnames from CT
  • dead names dropped
  • capped at 12 hosts
2

Talk to every server and see what it agrees to

scan/tls.py · scan/tls_client.py · Scanner._scan_tls

inhostnames→outcertificates + negotiated crypto

This is the heart of it. For each host, the scanner opens a real TLS connection on port 443 — eight at a time — and records what the server genuinely negotiates. It pulls down the full certificate chain as raw bytes and parses it itself.

It tries a verified handshake first, because whether that succeeds is the trust decision. If it fails, it reconnects without verification — an untrusted certificate still needs reading, since you need to know what's wrong with it.

The post-quantum probe

To test whether a server supports post-quantum key exchange, the scanner offers a hybrid group like X25519MLKEM768 but deliberately sends an empty key share. A server that supports it replies with a HelloRetryRequest naming that exact group. That reply is proof of support — obtained without ever completing a key exchange, so the probe is cheap and leaves nothing behind.

  • full cert chain
  • key + signature algorithms
  • expiry & hostname match
  • TLS versions SSLv3→1.3
  • every cipher suite
  • forward secrecy
  • hybrid ML-KEM support
  • interception detected
3

Check the web security headers

scan/http.py · Scanner._scan_http

inreachable hosts→outheader posture

On up to six live hosts, it fetches the site and reads the security headers — whether HTTPS is actually enforced, whether HSTS is set, whether a content security policy exists. Cheap checks, but they're the ones that get missed.

  • HSTS
  • CSP
  • HTTPS redirect
  • cookie flags
4

Check who can issue certificates and send mail as you

scan/dns.py · Scanner._scan_dns

indomain→outDNS posture

DNSSEC, CAA records (which certificate authorities are allowed to issue for you), and SPF plus DMARC — the two records that decide whether someone else can send email pretending to be you. Domain spoofing sits behind most invoice fraud.

Why it says "undetermined"

DNS answers over UDP get truncated when they're long, and a truncated SPF record looks identical to a missing one. The scanner retries over TCP; if that also fails it reports undetermined rather than claiming the record is absent. A measurement tool should never invent a finding it could not observe.

  • DNSSEC
  • CAA records
  • SPF
  • DMARC policy strength
5

Identify third-party components and their licences

scan/licences.py · Scanner._scan_licences

inserved page + headers→outcomponent list

From what the site actually serves, it identifies third-party components and maps them to SPDX licences — flagging the AGPL network clause, SSPL, GPL obligations and libraries that have reached end of life.

  • components
  • SPDX licences
  • copyleft obligations
  • EOL libraries
6

Turn observations into findings, scores and a plan

engine/rules.py · engine/scoring.py · engine/quantum.py · Scanner._analyse

inall raw observations→outreport

Only now does anything get judged. Every raw observation from stages 1–5 is passed through one rules module, which is the single place any severity is ever decided — so if you disagree with a verdict, there is exactly one file to argue with.

What stage 6 produces

Findings

engine/rules.py

Each problem, with a severity and the evidence that produced it.

Risk score and grade

engine/scoring.py

The findings weighted into a single number and an A–F grade.

Mosca deadline

engine/quantum.py

How long your data must stay secret, plus how long migration takes, against how long you have. If that sum exceeds the time remaining, you are already late.

Crypto inventory

build_inventory()

Every algorithm actually observed in use, each marked as safe, weakened or broken by a quantum computer.

Compliance mapping

engine/compliance.py

Findings mapped to NCSC's roadmap, NIST FIPS 203/204/205, CNSA 2.0, PCI DSS 4.0, UK GDPR Article 32, NIS2 and ISO 27001.

Remediation plan

engine/remediation.py

What to fix, in what order, with the highest-impact work first.

What you get back

  • HTMLThe client-facing report — the thing you actually send.
  • MarkdownFor pasting into tickets, wikis and internal docs.
  • JSONThe full structured result, for pulling into other systems.
  • CycloneDXA standards-compliant CBOM — a cryptographic bill of materials.

What it honestly cannot see

  • Anything not exposed to the internet. Internal systems, VPNs, SSH, code signing, database and backup encryption, and hardware security modules are all invisible from outside — and that is usually where the difficult cases live.
  • Anything behind an intercepting proxy. If corporate TLS interception sits between the scanner and the target, the certificate and TLS data describe the proxy, not your real server. The scanner detects this and says so rather than reporting the proxy's configuration as yours.
  • Whether a finding matters to your business. It measures configuration. Deciding which systems are worth protecting first is a conversation, not a scan.

Running it

# one domain, progress printed to the terminal
python -m quantumready scan acme.co.uk

# faster: skip the deep protocol probing (cipher enumeration is the slow part)
python -m quantumready scan acme.co.uk --fast

# write every output format
python -m quantumready scan acme.co.uk \
    --html-out report.html \
    --json-out result.json \
    --markdown-out report.md \
    --cbom-out cbom.json

# skip stages you don't need
python -m quantumready scan acme.co.uk --no-ct --no-dns --no-licences

# the live dashboard instead of a one-shot run
python -m quantumready serve
